# 저장소 설계

## 조회와 LRU

`MiniRedisStore`는 키·값과 만료 시각을 각각 해시맵에 저장합니다. LRU 순서는 이중 연결 리스트로 관리하며 별도 해시맵이 키의 노드를 가리킵니다. `SET`과 성공한 `GET`은 해당 노드를 최근 사용 위치로 옮깁니다. 조회와 순서 관리를 분리해 값을 찾을 때 리스트 전체를 탐색하지 않도록 했습니다.

## TTL

만료 시각의 해시맵은 현재 유효한 만료 설정을, 최소 힙은 정리할 시각의 우선순위를 제공합니다. 만료 설정을 바꾸면 과거 힙 항목이 남을 수 있으므로 정리할 때 현재 만료 시각과 비교합니다. `SET`은 기존 TTL을 해제합니다.

만료 처리는 명령 실행 시 수행합니다. `GET`·`EXISTS`·`TTL`은 해당 키의 만료를 확인하고, 일부 명령은 힙에서 만료된 키들을 정리합니다. 백그라운드 만료 스레드는 없습니다.

## 메모리 한도

메모리 사용량은 키와 값의 UTF-8 바이트 수 합계입니다. Python 객체나 자료구조 자체의 사용량은 계산하지 않습니다. 한도가 0이면 제한하지 않고, 한도를 초과하면 LRU 꼬리부터 제거합니다. 단일 항목이 한도보다 크면 저장을 거부합니다.

## 검증과 경계

저장소는 CLI 밖에서 사용할 수 있으며 생성자의 `clock`으로 시간을 주입할 수 있습니다. CLI 실행 경로는 `make smoke`로 확인합니다. 데이터 영속성, 네트워크 프로토콜, 실제 구독자에게 메시지를 전달하는 기능은 구현 범위에 포함하지 않습니다.
